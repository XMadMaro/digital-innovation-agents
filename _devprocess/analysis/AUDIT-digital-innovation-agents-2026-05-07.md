## Findings

### P2: Should Fix

#### M-1: Graph viewer renders untrusted graph data as HTML (CWE-79)

| Field | Value |
|-------|-------|
| **Severity** | Medium |
| **CWE** | CWE-79 |
| **Location** | `skills/dia-guide/tools/graph-viewer.html:268` |
| **Status** | Confirmed |

**Finding:** `showNodeInfo()` builds an HTML string from graph node fields such as `raw.label`, `raw.id`, `raw.type`, `raw.phase`, `raw.status`, `raw.epic`, `raw.path`, and connected node labels. The string is assigned to `document.getElementById('info').innerHTML`.

**Risk:** A malicious graph payload can inject markup or script when a user opens the viewer, pastes JSON, drops a file, or loads `?data=` / `?url=`. This is a local developer tool, so exposure is lower than a hosted web app. The likely impact is execution in the browser page, misleading links, or access to data available to that browser context.

**Remediation:** Build the details panel with DOM APIs and `textContent`. For file links, set link text via `textContent` and set `href` only after validating the path. Remove or restrict `?url=` loading to local files generated by the parser.

**Code suggestion:**

```js
const info = document.getElementById('info');
info.replaceChildren();
const title = document.createElement('h3');
title.textContent = raw.label || raw.id || '';
info.append(title);
```

### P3: Consider

#### L-1: Graph viewer loads runtime script from CDN without integrity check (CWE-829)

| Field | Value |
|-------|-------|
| **Severity** | Low |
| **CWE** | CWE-829 |
| **Location** | `skills/dia-guide/tools/graph-viewer.html:6` |
| **Status** | Confirmed |

**Finding:** The standalone graph viewer loads Cytoscape from `https://unpkg.com/cytoscape@3.30.2/dist/cytoscape.min.js`.

**Risk:** The version is pinned, which helps. The browser still trusts a remote CDN at runtime. A CDN outage breaks the tool. A compromised CDN response could execute code in the local viewer page.

**Remediation:** Vendor the minified Cytoscape file into the plugin bundle or load it from the local npm package during docs build. If a CDN stays, add an integrity attribute and a documented update procedure.

#### L-2: Windows hook wrapper forwards arguments without quoting

| Field | Value |
|-------|-------|
| **Severity** | Low |
| **CWE** | CWE-78 |
| **Location** | `hooks/run-hook.cmd:22` |
| **Status** | Confirmed |

**Finding:** The Windows wrapper calls Bash with `%2 %3 %4 %5 %6 %7 %8 %9`. Special characters in forwarded arguments can be interpreted by `cmd.exe`.

**Risk:** Current hook usage appears to pass a fixed script name and no attacker-controlled extra arguments. The risk becomes relevant if future hooks forward file paths, prompts, branch names, or config values through this wrapper.

**Remediation:** Keep the wrapper argument-free for current hooks, or replace the batch argument forwarding with a PowerShell wrapper that passes an array. If batch stays, quote each forwarded argument and document that hook arguments must not contain shell metacharacters.
